# collect/ 규약

- **수집기는 해석하지 않는다.** 여기서 하는 일은 (원본 아카이브 →
  `player_sample` 적재 → 상태머신 투입 → 세션 upsert)뿐이다.
  `context_origin` 을 쓰거나 선호 라벨을 붙이는 코드가 여기 있으면 버그다.
- **한 틱 = 한 트랜잭션.** 부분 기록된 샘플은 세션 재구성을 조용히 망가뜨린다.
- **204(유휴)와 오류를 절대 같은 카운터로 다루지 않는다.** 오류를 유휴로
  착각하면 활발한 청취 중에 조용히 폴링이 느려진다.
- **heartbeat 는 샘플 적재에 성공한 뒤에만 찍는다.** 살아 있음의 정의가
  "루프를 돌았다"가 아니라 "수집했다"여야 한다. 토큰이 죽은 채 도는
  프로세스가 heartbeat 를 영원히 쓰는 상황을 막는 것이 핵심이다.
- **수집이 끊긴 구간은 반드시 `collector_gap` 에 남긴다.** 레이트리밋 스킵,
  전송 오류, 프로세스 재시작 전부. recently-played 조정기가 어디를 봐야
  하는지 추측하지 않게 하는 것이 목적이다.
- 폴러와 recently-played 는 **한 프로세스의 두 태스크**다. 별도 프로세스로
  나누면 refresh token 회전이 어긋나 새벽에 수집이 죽는다.
