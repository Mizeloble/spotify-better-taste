# classify/ 규약

- **`rules.py` 는 순수 함수다.** `Evidence` 를 받아 `(Origin, reason)` 을
  돌려줄 뿐 DB 를 모른다. 그래야 결정표 전 행을 테스트로 고정할 수 있다.
- **판정마다 `reason` 을 남긴다.** "왜 이렇게 분류됐지"에 답할 수 없으면
  규칙을 고칠 수 없다. 재검토가 필요한 가정은 이름에 적는다
  (`artist_context_assumed`).
- **null context 의 기본값은 `unknown` 이다.** 오토플레이도 null 로 오고,
  그걸 `self` 로 넣으면 Spotify 의 추천으로 학습해 놓고 "내 취향 모델"이라
  부르게 된다. 양성 증거가 있을 때만 승격한다.
- **소유권 > 이름 패턴.** 결정표의 행 순서가 곧 우선순위다. 순서를 바꾸면
  `RULES_VERSION` 을 올릴 것.
- **규칙을 바꾸면 `RULES_VERSION` 을 올린다.** 안 올리면 `--stale` 이
  아무것도 고르지 않아 과거가 옛 규칙으로 남는다.
- **`--dry-run` 먼저.** 전이 행렬을 보지 않고 `--write` 하지 않는다.
- 분류는 네트워크를 쓰지 않는다. 플레이리스트 소유자 조회만 예외이고,
  그것도 예산 제한이 걸려 있다 (폴러가 굶으면 안 된다).
